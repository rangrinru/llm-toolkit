# 단어 선택과 어휘론 (Vocabulary & Diction)

자연스러운 한국어 문장을 만드는 첫 번째 단계는 **어휘의 뉘앙스를 바르게 파악하고 기계 번역투 단어를 배제하는 것**입니다.

---

## 1. 번역투 조사 및 상투 표현 대체 표

기계 번역이나 영문 직역에서 빈번하게 유입되는 상투적 표현들은 문장을 무겁고 어색하게 만듭니다. 아래 표를 기준으로 자연스러운 한국어 표현으로 치환합니다.

| 원문(직역/상투 표현) | 문제점 | 권장 대체 표현 | 예시 (Before → After) |
|---|---|---|---|
| **~에 대하여 / ~에 관하여** | `about` 직역. 불필요하게 문장이 늘어짐 | `~을/를`, `~의`, `~에 대해` | 보안 정책**에 대하여** 논의했다 → 보안 정책**을** 논의했다 |
| **~에 있어서 / ~에 있어** | 일본어 `〜において`, 영문 `in` 직역 | `~에서`, `~할 때`, `~에게` | 실무**에 있어서** 가장 중요한 점 → 실무**에서** 가장 중요한 점 |
| **~를 통해 / ~를 통하여** | `through` 직역. 물리적 통과가 아닐 때 남발 | `~로`, `~를 거쳐`, `~ 덕분에`, `~하여` | 업데이트**를 통해** 버그를 해결했다 → 업데이트**로** 버그를 해결했다 |
| **~의 경우(에는)** | 조건절 남발 (`in case of`) | 생략하거나 `~할 때`, `~라면` | 오류가 발생할 **경우** 문의하세요 → 오류가 **발생하면** 문의하세요 |
| **~를 필요로 하다** | `require`, `need` 직역 | `~가 필요하다`, `~해야 한다` | 관리자 권한을 **필요로 합니다** → 관리자 권한이 **필요합니다** |
| **~할 수 있다** | `can` 직역 남발 (단순 사실 서술인데 가능성으로 표현) | `~한다`, `~합니다` (실제 가능/권한일 때만 허용) | 설정을 통해 확인**할 수 있습니다** → 설정에서 **확인합니다 / 확인됩니다** |
| **~에 다름 아니다** | 일본어 번역투 관용구 | `~와 같다`, `~인 셈이다`, `~다` | 실패**에 다름 아닙니다** → 실패**한 것과 같습니다** |
| **~에 주목할 필요가 있다** | 영문 페이퍼 직역 (`It is worth noting that`) | `~가 중요합니다`, `~를 살펴봐야 합니다` | 성능 저하**에 주목할 필요가 있다** → 성능 저하**를 눈여겨봐야 합니다** |
| **하나의 ~ / 어떤 ~** | 부정관사 `a/an` 직역 | 생략 | 이것은 **하나의** 좋은 대안입니다 → 이것은 좋은 대안입니다 |
| **그것 / 그들** | 3인칭 대명사 `it/they` 직역 | 앞의 명사를 다시 쓰거나 생략 | **그것은** 시스템을 멈춥니다 → **이 오류는** 시스템을 멈춥니다 |

## 2. 명사 나열 억제와 용언(동사·형용사) 중심 서술

한국어는 동작이나 상태를 동사나 형용사로 시원하게 풀어쓸 때 가장 읽기 편합니다. 반면 영어나 일본어 번역문은 한자 명사를 줄줄이 엮어 쓰는 경향(명사화)이 짙습니다.

### 나쁜 패턴: 명사 + 명사 + `을/를 진행하다 / 수행하다 / 실시하다`
- ❌ 작업 환경의 최적화**를 진행하여** 성능 개선**을 도모합니다**.
- ⭕️ 작업 환경을 **최적화해** 성능을 **높입니다**.

- ❌ 사용자 요청에 대한 데이터의 검색**을 수행합니다**.
- ⭕️ 사용자가 요청한 데이터를 **검색합니다**.

- ❌ 신규 기능에 대한 테스트의 **실시가 요구됩니다**.
- ⭕️ 새 기능을 **테스트해야 합니다**.

## 3. 한자어와 순우리말의 자연스러운 조화

- **개념어/기술 용어**: 의미 전달의 명확성이 필요한 핵심 개념은 정제된 한자어나 널리 쓰이는 표준 외래어를 사용합니다. (예: `의존성`, `추상화`, `배포`, `캐싱`)
- **서술어/연결 표현**: 문맥을 잇는 어미, 부사, 일반 동사는 부드러운 고유어(순우리말)로 풀어내는 것이 좋습니다.
- **불필요한 과시적 한자어 순화**:
  - `익일` → `다음 날`
  - `금일` → `오늘`
  - `명기하다` → `적다`, `분명히 밝히다`
  - `일응` → `우선`, `일단`
  - `가료하다` → `치료하다`
  - `기여하다` → `도움이 되다`, `보탬이 되다`

## 4. 잉여 표현 및 의미 중복 제거

문맥상 이미 드러나 있는 의미를 단어로 중복 표현하면 글이 산만해집니다.

| 중복 표현 | 정리된 표현 | 비고 |
|---|---|---|
| 미리 사전 예고하다 | 미리 알리다 / 예고하다 | '사전'과 '미리' 중복 |
| 서로 상호 협력하다 | 서로 협력하다 / 상호 협력하다 | '서로'와 '상호' 중복 |
| 가장 최고의 성능 | 최고의 성능 / 가장 뛰어난 성능 | '가장'과 '최고' 중복 |
| 새로운 신규 기능 | 새로운 기능 / 신규 기능 | '새로운'과 '신규' 중복 |
| 매일 하루도 빠짐없이 | 매일 / 날마다 | 불필요한 강조 중복 |
| 박차를 가속화하다 | 박차를 가하다 / 가속하다 | 관용구 혼용 |

## 5. 외래어 표기 및 기술 용어 취급 원칙

1. **외래어는 국립국어원 표준 외래어 표기법을 준수합니다.**
   - 컨텐츠 ❌ → 콘텐츠 ⭕️
   - 메세지 ❌ → 메시지 ⭕️
   - 프레임워크 ⭕️, 파라미터 ⭕️ (파라메터 ❌)
2. **원문 유지가 가독성에 유리할 때**:
   - 코드 키워드, 함수명, 라이브러리 고유 명칭은 알파벳 원문을 그대로 유지합니다 (`async/await`, `React Hooks`, `git rebase`).
   - 굳이 어색하게 한글 음차하지 않습니다: `깃 리베이스를 진행하세요` ❌ → `git rebase를 실행하세요` ⭕️
