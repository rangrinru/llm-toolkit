# 한글 줄바꿈: 관찰과 예측

한글 프로그램 없이 "어디서 줄이 나뉘는지"를 알아야 띄어쓰기 벌어짐, 끝줄 한 글자, 칸 넘침을 고칠 수 있다.
`scripts/linebreak_sim.py` 는 글꼴 폭(Pillow 로 잰 글자 폭)으로 이를 흉내 낸다.

## 화면 캡처로 확인한 한글 동작

| 관찰 | 근거 |
|---|---|
| 문단 모양이 어절 단위(`breakNonLatinWord="KEEP_WORD"`)여도 한글 낱말이 줄 끝에서 잘렸다 ("확보 / 함.", "진 / 단하는") | 여러 캡처 |
| 영문·숫자는 낱말 단위로 통째로 넘어간다 → 양쪽 맞춤이면 앞줄 낱말 사이가 벌어진다 | 프로그램 이름이 든 칸 |
| 한 줄보다 긴 영문 낱말은 중간에서 잘린다 ("…_Diag_v1. / 1") | 좁은 표 칸 |
| ')' 는 줄 머리에 올 수 있다 ("…연구소 / )") | 좁은 표 칸 |
| `breakLatinWord="BREAK_WORD"` 로 바꿔도 영문이 글자 단위로 잘리지 않았다 | 바꾼 뒤 캡처 |
| 정렬을 LEFT 로 바꾸면 벌어짐은 사라지고 오른쪽 끝만 들쭉날쭉해진다 | 바꾼 뒤 캡처 |

## 예측기 계산 방식

- 글자 폭 = 글꼴의 글자 폭 × 장평(`ratio`) × (1 + 자간 %) × 글자 크기. 띄어쓰기는 0.5 em.
- 토막: 띄어쓰기 / 영문 낱말(통째) / 그 밖의 글자 하나. `. , ! ? %` 등은 앞 토막에, 여는 괄호는 뒤 토막에 붙여 계산.
- 첫 줄 폭과 둘째 줄 이후 폭은 내어쓰기(`intent`)만큼 다르다.

## 정확도

- 실제 캡처 6곳과 대조: 4곳은 줄 나뉨이 정확, 2곳은 한 글자 차이.
- 그래서 고칠지 판정할 때 칸 폭을 ±2 %(0.98, 1.0, 1.02) 바꿔 봐서 **모두** 괜찮을 때만 "고쳐졌다"고 본다.
- 문서에 쓰인 글꼴(돋움 등)이 PC 에 없으면 비슷한 글꼴로 재므로 오차가 커진다. `FONTFILE` 에 맞는 글꼴 파일을 넣는다.

## "보기 싫은 끝줄" 판정 (`Doc.bad_last_line`)

- 줄보다 긴 영문 낱말이 잘림
- 끝줄이 4 글자 이하(또는 줄 폭의 12 % 미만)이면서
  - 낱말 중간에서 끊겼거나
  - 왼쪽·양쪽 맞춤 문단이면(낱말 단위로 넘어가도 보기 싫음)
- 가운데 맞춤 칸의 "85% / 내외", "열화 진단 / 정확도" 처럼 낱말 단위로 넘어간 것은 자연스러우므로 제외
- 끝줄이 '(' '-' '[' 로 시작하면(괄호 설명, 글머리) 제외

## 고치는 순서

1. 정렬·내어쓰기 정리 (`tidy_paragraphs.py`) — 줄 나뉨 자체가 바뀌므로 먼저
2. 자간으로 끝줄 올리기 (같은 스크립트, -1 % 부터 -7 % 까지 한 단계씩)
3. 표 칸이면 열 너비 재분배 (`rebalance_columns.py`)
4. 그래도 안 되는 곳은 문장을 줄이자고 사용자에게 제안 (예: "평가 결과 자동 저장" → "평가 결과 저장")

자간을 -8 % 아래로 내리면 옆 문단보다 글자가 눈에 띄게 촘촘해진다. 그때는 문장을 줄이는 편이 낫다.
