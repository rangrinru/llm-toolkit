# Hallmark 빌드 과정 (7단계)

> 출처: [hallmark SKILL.md](https://github.com/Nutlope/hallmark/blob/main/skills/hallmark/SKILL.md) § Flow, [flow.md](https://github.com/Nutlope/hallmark/blob/main/skills/hallmark/references/flow.md)

| 단계 | 이름 | 하는 일 |
|---|---|---|
| 0 | Pre-flight | 묻기 전에 프로젝트부터 읽는다: `design.md`, 브랜드 스펙, 폰트, 팔레트, 프레임워크, 실제 제품(URL, dev 서버) |
| 1 | Ask once | 재료, 대상, 목적, 톤 4가지를 **한 번만** 묻는다 |
| 2 | Shape | 재료 목록 정리 → 방문자의 job → 페이지 구조 설계 → 시그니처 정하기 |
| 3 | Direction | 테마 3개를 받아서 하나 선택, 또는 custom이면 자유 디자인 |
| 4 | Load | 레이아웃, 이미지, 크래프트, 장르, 테마 문서와 게이트를 필요한 만큼만 로드 |
| 5 | Picks block | 결정 사항을 한 번에 정리해 보여줌 (사용자가 방향을 바꿀 수 있는 지점) |
| 6 | Build | **히어로 먼저** 만들고 검사 → 통과하면 나머지 섹션 |
| 7 | Sweep | sloplint 렌더 검사 → 판단 게이트 → 새 컨텍스트 리뷰 → 필요한 소재 요청 |

## 1단계: 사전 질문 템플릿 (한국어 버전)
```text
만들기 전에 4가지만 알려줘.
1. 재료(가장 중요): 페이지에 보여줄 수 있는 것.
   스크린샷이나 화면 녹화(앱 URL이나 폴더를 알려주면 직접 실행해서 찍을게), 직접 찍은 사진,
   실제 수치(고객 수, 가동률, 가격), 말한 사람 이름이 있는 인용문, 사용 허락 받은 로고.
   없으면 대체 이미지 슬롯으로 두고, 수치, 인용문, 로고는 절대 지어내지 않아.
2. 대상: 누가 쓰고 무엇을 중요하게 생각하는지
3. 목적: 페이지가 유도해야 하는 단 하나의 행동
4. 톤: 극단 하나를 골라줘 (editorial, brutalist, soft, utilitarian, luxury, playful, technical, austere).
   "깔끔하고 모던하게"는 톤이 아니야. 4~8단어 분위기 묘사와 기준 색이 있으면 함께.
아니면 "그냥 진행"이라고 하면 내가 추론해서 무엇을 골랐는지 알려줄게.
```

## 2단계: Shape 핵심
- **재료 목록**: *real*(실제로 주어진 이름, 주장, 수치, 장소, 이미지) / *pictures*(보여줄 그림과 출처) / *absent*(없는 증거: 로고, 인용, 지표)
- **Job**: 방문자가 하러 온 일(구독, 예약, 방문, 구매, 가입, 문의, 청취...) → 그 업종의 실제 사이트들이 행동 버튼을 어디에 두고 어떻게 끝나는지를 따른다
- **Signature**: 방문자가 기억할 단 하나. 가장 강한 실제 소재를 첫 화면에 가장 좋게 보여주기
- **Mirror test**: 같은 업종의 다른 프롬프트도 똑같은 조합을 받을까? 그렇다면 결정 하나를 바꾼다

## 5단계: Picks block 예시
```markdown
**Hallmark · v2.0.0**
- **Shape** · Workbench · genre modern-minimal · job: 가입, 히어로와 가격 옆에 버튼
- **Theme** · Coral (따뜻한 회색, 코랄 신호색 하나, General Sans, 부드러운 pill)
- **Chrome** · nav: 가장자리 정렬, 워드마크 + 버튼 하나 · footer: 워드마크 아래 링크
- **Hero** · 1~5열 제목, 6~12열 560px 슬롯
- **Signature** · 연체된 결제를 추적하는 송장 목록, 히어로에서 실제로 동작
- **Sections** · Hero · Pinned · Switcher · Table(가격) · Footer
- **Material** · real: 2분 설정, CSV 가져오기 · pictures: 히어로의 송장 목록 · absent: 로고, 인용, 지표
- **Sweep** · 빌드 후 실행
```

## 6단계: 빌드 규칙 요약
- **한 화면에 한 아이디어, 크게.** 히어로 제목 7단어(50자) 이하, 설명 한 문장 12단어 이하, 버튼 1~2개
- 섹션 6~9개(히어로, 푸터 포함), 보이는 단어 450개 이하. 풍성함은 글이 아니라 크기와 그림에서
- **설명하지 말고 보여주기**: 사용자 이미지 > 실제 제품 스크린샷 > 실제처럼 만든 제품 > 라이브러리 사진. 사진은 히어로 아래 페이지의 1/3 이하, 사진 섹션 2개 연속 금지
- **페이지 불변 조건**: 주요 버튼 스타일 1개, 컨테이너 폭 1개, 히어로 아래 컬럼 간격 1개, 중첩 레벨마다 radius 1개
- **타이포/모션**: 폰트 패밀리 최대 2개(보조 1개 추가 가능), 본문 16px 이상, 제목은 한 굵기 한 색. 컨트롤 8가지 상태, transform/opacity만, 리빌 효과 최대 1개
- 기존 스타일시트는 덧붙이기만 하고 프로젝트의 토큰 이름 재사용

## 7단계: Sweep
1. `sloplint --render`로 FAIL이 없을 때까지 수정
2. 판단형 게이트 검토, WARN 확인
3. **새 컨텍스트의 리뷰어**가 최종 판단 (recapture / rebuild / fix / ship)
4. 각 슬롯에 들어갈 소재와 크기, 페이지를 가장 크게 개선할 소재 하나를 요청
5. 결과 기록 예: `Floor 0 FAIL · Reflex 2 (1 waived) · finish-review: 3 resolved`
