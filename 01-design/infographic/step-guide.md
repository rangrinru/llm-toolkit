# 단계 가이드 (프로세스 인포그래픽)

> 대상 모델: Claude (Design 캔버스) / GPT | 마지막 테스트: 2026-11-16
> 출처: 직접 작성

## 언제 쓰나
- 작업 흐름이나 처리 단계를 한 장(영상 프레임, 슬라이드, 문서 그림)으로 보여줄 때
- 같은 내용으로 시안을 여러 개 뽑아 비교하고 싶을 때

## 프롬프트
```text
아래 단계를 한 장짜리 단계 가이드 그림으로 만들어라.

[용도] {용도} · 크기 {가로×세로} · 노출 {N초}
[보는 사람] {청중}
[먼저 읽힐 것] 단계 번호 → 단계 이름 → 직접/자동 구분

[내용] — 빠짐없이 쓰고, 여기 없는 사실은 지어내지 말 것
- 제목: {제목}
- 단계마다 이름 / 하는 곳 / 직접·자동 / 남는 것:
  1. {단계 1} / {하는 곳} / {직접|자동} / {결과물}
  2. {단계 2} / {하는 곳} / {직접|자동} / {결과물}
  ...
- 강조 문장: "{한 문장}"
- 마지막 줄: {후속 기능이나 다음 단계}

[스타일 · 은유] {아래 프리셋 중 하나, 또는 직접}
[색감] 바탕 {hex} · 글자 {hex} · 강조 {hex} — 강조색은 {쓰는 자리}에만
[폰트] 제목 {폰트} / 본문 {폰트} / 숫자 {폰트}
[문장 톤] {해요체 | 명사형 | 지시문 | 보고서체 | 문답} — 예) "{예문}"
[레이아웃] {예: 가로 5칸, 칸 사이 화살표, 아래 범례}
[금지] {예: 그라데이션, 이모지, 그림자, 3색 이상}

시안을 여러 개 만들면 시안마다 [스타일 · 은유] [색감] [폰트] [문장 톤]을 다르게 하고, 내용은 그대로 둔다.
```

## 변수
- `{용도}` · `{가로×세로}` · `{N초}`: 어디에 쓰는지. 글자 크기와 정보량이 여기서 정해진다
- `{청중}`: 누가 보는지
- `{단계 n}` · `{하는 곳}` · `{결과물}`: 단계마다 '어디서 · 무엇이 남는지'까지 주면 정보량이 크게 늘어난다
- `직접|자동`: 사람이 하는 단계와 저절로 넘어가는 단계를 나누면 범례 · 색 구분이 생긴다
- `{한 문장}`: 화면의 초점이 되는 문장

## 프리셋 A — 구조를 바꾸는 은유
`[스타일 · 은유]` 이하에 그대로 붙여 쓴다.

**스위스 타이포그래피** — 큰 숫자가 주인공, 장식 없음
```text
[스타일] 스위스 타이포그래피(International Typographic Style). 12단 그리드, 왼쪽 정렬, 흰 바탕 + 검정 + 빨강 1색만. 큰 숫자가 주인공
[금지] 그림자, 둥근 카드, 아이콘, 그라데이션
```

**지하철 노선도** — 단계 = 역
```text
[은유] 지하철 노선도. 단계 = 역, 자동으로 넘어가는 구간은 다른 색 노선, 여러 갈래로 나뉘는 단계는 환승역
[내용] 역마다 남는 파일을 출구 안내처럼 작게
[스타일] 역 표지판처럼 위쪽 검정 띠에 흰 제목. 노선 굵기 12px, 역은 흰 원 + 굵은 테두리
[후속 기능] '환승 안내'로
```

**블루프린트 도면** — 정밀하고 기술적
```text
[스타일] 공학 도면(블루프린트). 남색 바탕 + 얇은 흰 선 + 모눈. 바깥 테두리와 오른쪽 아래 표제란
[표현] 단계는 부품 상자(S-01 ~ S-0N 코드), 사이는 화살표 선, 자동 구간은 점선 + '자동' 치수 표기
[글꼴] 코드 · 파일 이름은 고정폭, 한글은 산세리프
[톤] 정밀하고 기술적, 장식 없음
```

**에디토리얼** — 잡지 펼침면
```text
[스타일] 잡지 펼침면. 크림 바탕, 세리프 큰 제목 + 산세리프 본문, 테라코타 강조 1색
[구성] 왼쪽 40% 제목 · 리드문, 오른쪽 60% 목차처럼 번호 매긴 단계 목록, 가는 줄로 구분
[강조 문장] 인용구처럼
[여백] 넉넉하게 — 글자보다 여백이 많아 보이게
```

## 프리셋 B — 색감 · 폰트 · 문장 톤까지 정한 것

**따뜻한 안내 (해요체)**
```text
[색감] 살구빛 바탕 #FFF4EC, 강조는 코랄 #E8613C 한 색, 글자는 짙은 갈색 #3B2A20. 코랄은 숫자와 '저절로' 표시에만
[폰트] 제목 Jua(둥근 굵은 고딕), 본문 Gowun Dodum
[문장] 해요체로 말 걸듯이. 예) '저장이 끝나면 알아서 바뀌어요'. 단계 이름은 동사로 짧게, 설명은 한 문장
[레이아웃] 둥근 흰 카드 가로 배치, 카드 사이 점선 화살표, 아래에 '그다음엔 이런 것도 해요' 줄
[금지] 영어 대문자, 딱딱한 명사형 문장
```

**로그 출력 (터미널)**
```text
[색감] 거의 검정 #0B0F0C 바탕, 형광 초록 #3CF08A는 '자동 · 완료'에만, 나머지는 회색 #9BA59E
[폰트] Nanum Gothic Coding 하나만 — 고정폭으로 열 맞춤
[문장] 로그 줄처럼 짧은 명사형. 예) '[02] 자동  변환 … 완료'. 단계마다 한 줄
[레이아웃] 창 테두리 하나, 위에 파일 이름 줄, 위에서 아래로 줄 단위. 마지막 줄에 커서
[금지] 아이콘, 둥근 모서리, 그림자
```

**산업 안전 표지**
```text
[색감] 안전 노랑 #FFD400 + 검정 #111111 두 색만. 위 · 아래에 노랑/검정 사선 띠
[폰트] 제목 · 숫자 Black Han Sans, 본문 Gothic A1 Bold
[문장] 짧은 지시문(~한다 / ~된다). 예) '저장이 끝나면 자동 변환된다'. 한 줄 15자 안팎
[레이아웃] 검정 번호 블록 + 노랑 바탕 큰 글자. 자동 단계는 검정 바탕으로 반전
[금지] 3색 이상, 가는 글꼴, 파스텔
```

**미니멀 모노톤**
```text
[색감] 오프화이트 #FAFAF8, 글자 #1A1A1A, 보조 회색 #707070 하나. 강조색 없음 — 굵기와 크기로만 구분
[폰트] 숫자 Hahmlet(가는 세리프), 글자 Noto Sans KR 300 · 500
[문장] 단계는 두 글자 단어. 설명은 8자 이내
[레이아웃] 화면 70%는 비움. 가운데 얇은 가로선 하나 위에 점(단계 수만큼)
[금지] 박스, 배경 칩, 아이콘, 색
```

**파스텔 · 대화형**
```text
[색감] 단계마다 다른 파스텔: 라벤더 #E9E3FF · 민트 #D7F3E6 · 피치 #FFE2D1 · 하늘 #DCEBFF · 레몬 #FFF3C4, 글자는 남색 #1F2547
[폰트] 숫자 · 제목 Bagel Fat One, 본문 Gothic A1
[문장] 질문 → 답 대화형. 예) 'Q. 변환은 누가 해요? A. 저장이 끝나면 알아서!'
[레이아웃] 살짝 기울어진(-2° ~ 2°) 스티커 카드
[금지] 회색 바탕, 반듯한 표
```

**보고서 표**
```text
[색감] 흰 바탕, 네이비 #1F3A5F 머리줄, 회색 줄무늬 #F3F5F8, 강조색 없음
[폰트] IBM Plex Sans KR (본문 400, 머리 700)
[문장] 보고서체 '~함 / ~됨'. 예) '저장 종료 시 자동 변환됨'
[레이아웃] 한 장짜리 표: No · 단계 · 하는 곳 · 방식 · 남는 것 · 설명. 표 아래 각주로 후속 기능과 '자동'의 뜻
[금지] 아이콘, 둥근 카드, 큰 장식 글자
```

## 메모 (결과, 팁, 실패 사례)
- 모호한 프롬프트("단계 가이드 깔끔하게 만들어줘")는 가운데 정렬 · 같은 카드 · 아이콘 · 보라 강조로 수렴했고, 직접/자동이나 결과물 같은 정보는 빠졌다.
- 단계마다 '하는 곳 · 남는 것'과 직접/자동 구분을 넣자 같은 크기에 훨씬 많은 정보가 들어갔다.
- 기울어진 카드, 사선 띠는 영상으로 뽑을 때 가장자리가 계단처럼 보일 수 있다.
- 미니멀 프리셋은 정보가 가장 적게 남는다. 설명이 중요한 화면에는 보고서 표 · 에디토리얼 프리셋이 낫다.
